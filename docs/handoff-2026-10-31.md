## How this machine is set up
- Project lives at `/Users/brad/Documents/agency-os` (internal disk, not the T7). The owner is the only user; they are not a developer, so explain changes in plain English, one or two sentences before acting.
- The CRM runs as a background launchd service, `com.agencyos.crm`, on `http://127.0.0.1:3000`, as a **production build**. After any code change: `cd crm && npm run build`, then `launchctl kickstart -k gui/$(id -u)/com.agencyos.crm`. Log: `~/Library/Logs/agency-os/crm.log` (the first place to look for any "Application error" and its digest). A copy of the service file is `scripts/com.agencyos.crm.plist`; notes are in `docs/SETUP.md`.
- Because it is a production build, **Next.js hides the text of errors that server actions throw**. Actions must `return { error: "..." }` for anything a user can trigger (the form wrapper `components/ToastForm.tsx` shows it). Throwing only gives a vague message with a digest code.
- Tests: `cd crm && npm test` (218 passing). Typecheck: `npx tsc --noEmit`. Run both before committing, and do not chain a commit after a failing test.
- Commit and push only with `node tools/git/sync.mjs "message"` (needs `GITHUB_TOKEN` in `.env`, set). Repo: `bdravie/agency-os`, branch `main`. End commits with the Co-Authored-By line from the session instructions.
- Database: Neon (key was replaced yesterday and works). Schema only changes through a new migration in `db/migrations/`, applied with `npm run db:migrate` from the repo root (dbmate is installed there). Never edit an applied migration. Take care with deletes: always show the owner what will go, use a transaction, and roll back unless the counts match.
- `uv` and `pg_dump` are **not installed** on this Mac, so the Python tools (`agency.backup` etc.) cannot run here. Neon point-in-time restore is the only backup in practice.
- A project hook (`.claude/hooks/guard-bash.sh`) blocks any command that reads `.env`, and wrongly flags the Anthropic SDK call `messages.create` as an SMS send. Do not work around it. To exercise app code against the real database or AI, write a small `.mts` script in the session scratchpad and run `npx tsx --env-file=../.env <script>` from `crm/` (it never prints secrets).
- Keep running costs low: AI wording is click-only, with caps and model settings in `.env` (`SUGGEST_MODEL`, `DM_MODEL`, `RAPPORT_MODEL`, `OUTREACH_MODEL`, `UPWORK_MODEL`, daily caps). The Haiku/Sonnet 5.5 models spend tokens on reasoning, so low `max_tokens` (100 to 1800) gave empty or cut-off replies: use generous limits and validate the output.
- `SENDER_NAME` and `BUSINESS_NAME` are set (Bradley, CLRS Web); every draft carries them and the opt-out line.
