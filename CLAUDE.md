# Agency OS

This repo runs a one-person AI automation agency based in the UK. At its centre is the owner's **own CRM**: one Postgres database (hosted on Neon's free tier, London region, because the laptop has no disk space for Docker) and one Next.js app running locally. It is for the owner's use only (not sold), and it is the single place for all business data: leads, deals, clients, quotes, content, proposals and tracking.

Around the CRM sit:

1. **Selling tools**: automation catalogue and quotes, Upwork proposal drafter, content engine, inbound lead handling.
2. **Lead Engine and Social Engine**: modules that write into the same database.
3. **Demo builds** in `demos/` that the agency sells to clients. Each must be easy to show in a 2-minute Loom and easy to copy for a new client.

The step-by-step build order is in `BUILD_PLAN.md`. Work through it one milestone at a time and tick off the done-checklist as you go.

## Business rules (important)

- Client automations in phase 1 handle **business data only**: content, ad metrics, sales and stock totals, internal admin. Do not add features that store a client's end customers' personal data unless the owner asks and confirms a data processing agreement is in place.
- **Scraped leads are company-level only**: company name, website, phone, address, ratings, generic emails (info@, hello@, contact@, enquiries@), social links. Drop named contact persons and personal emails from any scraper output (exhibitor lists especially) before saving.
- **Contacts** (named people) are only added when that person has engaged: filled in a form, booked a call, replied, messaged, or became a client. Record how they arrived in `contacts.consent_basis`.
- Outreach tools only target **limited companies** (Companies House status `active`, type `ltd`/`llp`/`plc`). Never build anything that sends SMS or cold messages automatically. Drafting is fine; the owner sends. **The exceptions (approved by the owner) are click-to-send email (2 Nov 2026) and click-to-post to the owner's own LinkedIn profile (12 Nov 2026), see below: every other "the app never sends" statement in this file still holds for DMs, SMS and social messages, and for email and the owner's LinkedIn posts it now means "never without the owner's click".**
- Every outbound email template includes the sender's real name, business name and a one-line opt-out ("Reply 'no' and I won't email again").
- The `suppression` table (emails, domains, phone numbers, company numbers) is checked by every list-building and outreach feature. The `lead_gate` database view is the single definition of "may be contacted": a verified active ltd/llp/plc (or, as the one owner-approved exception below, a company the owner has bypassed with their password), not opted out, not suppressed. Email, social and SMS drafts, lists and logged sends all go through it (`crm/lib/complianceGate.ts`, `agency.compliance`), and a database trigger refuses to log a send that fails it. New leads start unverified, so blocked, until looked up on Companies House. Opt-outs are permanent: never clear one unless it was recorded by mistake.
- Scrapers respect robots.txt, rate limits and each tool's free caps, and print what each run cost.
- Audits record a client's recurring tasks as roles and hours, never people's names, emails or phone numbers (the app refuses contact details). Tasks involving special-category data are scored but held out of the recommendations until a data processing agreement and DPIA are in place. AI audit reports are drafted only when the owner clicks, with the model set by `AUDIT_MODEL`.
- Call transcripts are added only for calls where everyone knew they were recorded. Emails, phone numbers and speaker names are masked before saving, the original upload is never kept, and AI analysis runs only when the owner clicks, with the model set by `CALLS_MODEL`. **Calls can be phone calls, video calls or in-person meetings (`calls.kind`, built 8 Nov 2026)**: an in-person meeting starts on notes, since there is no recording. The owner's own notes (source `notes`) can be edited after saving, as can any call's title, date and type (`saveCallDetails`, `crm/lib/callEdit.ts`, `crm/components/CallEditor.tsx`): edited notes are masked again like new ones, a transcript or removed text is never editable, saving never runs the AI, and if notes change after an analysis the page says it may be out of date (`calls.notes_edited_at`) until the owner clicks Analyse again. Notes are business observations only, never details about a client's own customers.
- Outcomes record business metrics only (missed calls, response times, bookings, hours), never data about a client's end customers. Client reports, case studies and testimonial emails are drafts the owner sends: a case study needs the client's approval before use, AI wording runs only when clicked (`OUTCOMES_MODEL`), and the email carries the owner's name, business name and opt-out line.
- Enablement keeps a client's trained staff as a name and role only (never emails or phone numbers) with a 1-3 skill level. It is a training record, not a performance rating, and anyone can be removed on request. Training files are stored in the database and served as downloads only, from an allow-list of file types.
- Offer research reads only a company's own public website (up to four pages, robots.txt respected, public https addresses only) and never social platforms or named individuals. Opted-out and suppressed companies are not researched. The AI step runs only on click (`SUGGEST_MODEL`), must cite findings, and flags any suggestion that would handle the business's customers' personal data as needing a data processing agreement first.

Settings: `LINKEDIN_CLIENT_ID`, `LINKEDIN_CLIENT_SECRET`, optional `LINKEDIN_REDIRECT_URI` (default `http://127.0.0.1:3000/api/linkedin/callback`, so connect on the Mac, not the phone) and `LINKEDIN_API_VERSION` (YYYYMM; LinkedIn retires versions after about a year); setup in `docs/SETUP.md` section 2d. - **Calendar, two-way sync and click-to-book meetings (approved by the owner, 3 Nov 2026; built)**: the owner connects their own Google Workspace business calendar (`/calendar`, same Google sign-in app and callback as the mailboxes, scope `calendar.events` only, token stored encrypted in `calendar_connections`; `crm/lib/gcalAuth.ts`, `crm/lib/gcal.ts`). The invitation text carries the owner's real name, business name and the one-line opt-out ("Reply 'no' and I won't email again"); the guest cannot change or forward it. A daily limit applies (`CALENDAR_DAILY_CAP`, default 10) and a clash with an existing event is flagged. Booking can move an early-stage deal to Call booked (ticked by default). Cancelling is a click and Google emails the guest. Notes in an invitation are business topics only. The CRM never reads replies to invitations, and never books or sends anything automatically. Disconnecting deletes the saved copy of the calendar (tasks stay).

## Stack

- **Database**: hosted Postgres 16+ on **Neon** (free tier, AWS eu-west-2 London), reached via `DATABASE_URL` with `sslmode=require`. The schema lives in SQL migrations in `db/migrations/`, run with dbmate from npm (`npm run db:migrate`; no Docker). Never change the schema any other way; never edit an applied migration, add a new one. Docker Compose (local Postgres/n8n) is optional for later, once there is disk space.
- **Where the project lives**: on the T7 drive at `/Volumes/T7/agency-os 2` (exFAT). Because exFAT cannot hold macOS metadata, macOS leaves `._*` sidecar files next to files; they are git-ignored and `scripts/clean-sidecars.sh` deletes them. Python's environment lives on the internal disk (`~/.venvs/agency-os`) and `.venv` is a link to it, because installing packages onto exFAT fails when sidecars appear. Use `uv run python` (the bare `python3` on this Mac is Apple's placeholder). On the Mac where the project sits on the internal disk (3 Nov 2026), `uv` comes from Homebrew (`brew install uv`) and `uv sync` builds a normal `.venv` in the repo; the CRM runs its Python tools with `.venv/bin/python` when it exists (`pythonCommand` in `crm/lib/launch.ts`), so it does not need `uv` on its PATH, and a missing environment now says "run uv sync" instead of `spawn uv ENOENT`. The T7 must be plugged in to work on the project.
- **Git**: no system git (no disk space for Xcode). Commit and push with `node tools/git/sync.mjs "message"` (isomorphic-git) after every change.
- **Putting a change live**: `bash scripts/update-crm.sh` in the Mac's Terminal app (`tools/crm-update/update.mjs`, rules in `rules.mjs`, details in `docs/SETUP.md`), never a build in place. Only this command may change `crm/.next`, the folder the running CRM serves from: `crm/next.config.mjs` refuses a plain build and gives `npm run dev` its own folder. From the container, use `NEXT_DIST_DIR=.next-container` for any build or `next start`. Database changes must leave the previous version working, because going back restores the code only.
- **CRM app**: Next.js (App Router, TypeScript) in `crm/`, using the `pg` driver with parameterised queries. Single user: password from `APP_PASSWORD`, signed session cookie. The session lasts 12 hours at most and the cookie ends when the browser closes; opening `/login` always signs you out (`crm/middleware.ts`), so the password page never sits in front of a working app. Every page and API route requires login except `/api/webhooks/*`, and every webhook verifies its signature or secret. Listens on 127.0.0.1:3000. **On the phone (12 Nov 2026)**: reached privately through Tailscale (`tailscale serve`, never `funnel`), with the address in `CRM_EXTRA_ORIGINS` for server actions, and installable to the home screen (`app/manifest.ts`, `app/apple-icon.tsx`, `lib/appIcon.tsx`; only the manifest and icons skip login, `PUBLIC_ASSETS` in `crm/middleware.ts`); steps in `docs/SETUP.md`.
- **Python tools**: Python 3.12 with `uv`, code in `src/agency/`, tests in `tests/` (pytest), `psycopg` for the database. All tracking goes through one `log_activity()` function writing to the `activities` table.
- **AI**: the official `anthropic` SDK. Model choice lives in one place, `src/agency/llm.py` (and a matching `crm/lib/llm.ts` if the app needs AI):
  - `claude-opus-5-5` for hard reasoning or long documents (use sparingly)
  - `claude-sonnet-5-5` as the default for writing and agent logic
  - `claude-haiku-5-5` for high-volume, short tasks (classification, first lines, scoring)
  - Never force `tool_choice` in `askStructured`: Sonnet 5.5 rejects it with a 400 ("tool_choice: type tool and any are not supported for this model", seen 11 Nov 2026), which breaks every structured AI step. The prompt tells the model to call the submit tool, and a plain-text JSON reply is parsed as a fallback.
- **Automation runner**: n8n, deferred for the agency's own jobs. For demos it runs locally with `npx n8n` (free Community Edition, checked with 2.47.5 on 12 Nov 2026; the first install takes several minutes because one component compiles from source): import workflow files with `npx n8n import:workflow --separate --input=<folder>`, run one with `npx n8n execute --id=<id>`, and remember a timer and an error workflow only run once a workflow is published. ## Working method (self-annealing)

In this repo, **directives** are the living instruction documents: this file, `BUILD_PLAN.md`, `prompts/*.md`, `docs/*.md` and each demo's `README.md`. **Tools** are the scripts and commands that do the work: `uv run python -m agency.*`, `npm run db:migrate`, `node tools/git/sync.mjs`, `bash scripts/update-crm.sh`, `scripts/*`.

**1. Self-anneal when things break** - Read error messages. Check logs. Update the script that failed. Add test cases. Fix the root cause. Don't just try the same thing again.
- Update the directive with what you learned (API limits, timing, edge cases).

**2. Update directives as you learn** - Directives are living documents. When you discover API constraints, better approaches, common errors, or timing expectations, update the directive. But don't create or overwrite directives without asking unless explicitly told to. Directives are your instruction set and must be preserved (and improved upon over time, not extemporaneously used and then discarded).

### Self-annealing loop

Errors are learning opportunities. When something breaks:
1. Fix it
2. Update the tool
3. Test the tool
4. Update the directive
5. System is now stronger
